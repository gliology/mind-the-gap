# Release notes

Each release says what changed and what it was tested on. The tables are rendered from the
official test runs ([test results](test-results.md)) when the release is made, and stay as
they were for that release.

## 1.0.0-rc.1

The first release candidate of mind-the-gap 1.0 and its derivation scheme, `mtg1`. Keys and
certificates derived by a release candidate are expected to stay the same in 1.0, but the
release candidate is for testing: provision spare cards with it, not the ones in daily use.

- **Two seeds.** A card seed administers cards (per-card management keys, puks, admin pins
  and identifiers, bound to each card's serial); a key seed derives an identity's keys and
  certificates. One phrase can be both. See [key derivation](derivation.md) and the
  [recommended flows](flows.md).
- **One verb per action**: `list`, `check`, `init`, `upload`, `rotate`, `pin`, `wipe`,
  `revoke`, `publish` and `ungap` act on both applets, or on one with `--app`; `generate`,
  `trust` (OpenPGP), `run`, and the session's `set`, `unset` and `quit` stand apart. See
  [commands](commands.md).
- **One name per option**, the same as a flag, a config key, a `set` and a `MIND_THE_*`
  variable, with defaults per applet in `[piv]` and `[pgp]` tables. See
  [options](configuration.md).
- **Ceremonies**: recipes of commands that `run` follows step by step, with dry runs and
  recorded transcripts. An image built with one checks it when it is built, names it in the
  login banner, and runs its first recipe on a bare `mind-the-gap`. See
  [ceremonies](ceremonies.md).
- **Plumbing mode** for scripts and unattended hosts: JSON on stdout, nothing asked. See
  [plumbing mode](interfaces.md#plumbing-mode).
- **A command line that says what it takes**: `--validity` in calendar units (`730d`, `2w`,
  `6mo`, `2y`) counted from the generation's day, so `2y` ends on the anniversary; what the
  options lack told all at once, before any seed is stretched; `set` alone showing the
  defaults behind their layers and the config files read, on the command line too, with
  `set --save` and `unset --save` to write the user's file and `set --help` to name every
  setting; help that lists a verb's own options first, and a session's own help; tab
  completion in the session, and of `run`'s recipes in bash, zsh and fish; `--version`
  naming the derivation scheme, and on the image the source revision; and an [option
  reference](options-reference.md) rendered from the command line itself.
- **Rotation and revocation**: generations by date, previous decryption keys kept in
  retired PIV slots, revocation lists at a URL, and moving off a leaked key seed. See
  [rotation, revocation and recovery](rotation.md).
- **More cards**: YubiKey 4 and 5, Nitrokey 3, Solo 2 and Gnuk, with RSA keys up to 4096
  bits, P-384 and Curve25519 where the card takes them, and the KDF data object where it
  needs one. See [supported cards](supported-cards.md).

Every card provisioned by a build of the 1.0 branch before this release candidate (those
builds were never released) derives differently now: `init` and `upload` it again, under a
new date, as [compatibility](compatibility.md#cards-provisioned-before-100-rc1) describes.
OpenPGP cards provisioned by the 0.x releases keep working with `--legacy`, and PIV cards of
0.x start over ([upgrading from 0.x](compatibility.md#upgrading-from-0x)).

The command line changed for such a build's users as well:

- A validity spelled another way, `2years` or `24m`, in a config file or in
  `MIND_THE_VALIDITY` now stops every command with an error that names the file or the
  variable, `set --save` included, as a file is read before anything runs: edit the line to
  calendar units, `validity = "2y"`, or delete it, and give the variable as `2y`.
- A certificate issued with `--validity` now ends on the calendar anniversary of its day, where
  it ended a fraction of a day off before, so the same options issue other certificates, with
  other serial numbers, than an earlier build did; the keys are the same.
- `check` without the identity's name now fails before it shows the record, as every one-shot
  command fails before it derives when an option is missing: give `--name` to see the seed id.
  `check --plumbing` without it reports the error and no `seed_id`.
